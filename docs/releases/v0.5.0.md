# HaTickets v0.5.0 Release Notes

发布日期：2026-07-11
对比基线：`v0.4.1 (3e5291f)` → `master (bb92a96)`
变更规模：43 commits，70 files changed（`+16017 / -2751`）

## 版本定位

`v0.5.0` 把 v0.4.1 之后（2026-05 ~ 07）沉淀的工作打包发布。主线是**从「能抢」走向「敢用」**：

- **资金误操作防护重构**（BREAKING）：真实下单必须显式 `--commit`，裸 `--yes` 不再能触发付款；
- **一轮用户视角圆桌评审**落地为 8 项可验收 backlog（安全闸门 / 配置健壮性 / 可编排性 / 文档单源）；
- **抢票正确性与信任修复**：4 个开放 issue（#41/#45/#50/#51）+ probe 模式不再虚报成功；
- **多场次 / 价格 / NLP / 页面探测健壮性**的一整轮止血（#25/#31/#26/#24/#23/#28）；
- `damai_app.py` **包化重构** + **结构化可观测性**；
- 真机验证过程另抠出并修复 4 个只有真机能暴露的 bug。

整体方向：**安全 > 正确 > 可维护 > 易用**，均以单测 + 真机双重验证。

## 主要功能提升

### 1) 资金误操作防护重构（核心变更，BREAKING）

背景：旧版 `start_ticket_grabbing.sh --yes`（不带 `--probe`）会**静默**把配置改写为 `if_commit_order=true` 并真实下单——安全探测与真实付款之间只差一个单词，漏敲极易误付款。

- 新增 `--commit` 旗标，作为**唯一**会改写配置为真实下单并提交订单的授权；
- 裸 `--yes` / `-y` 单独出现**直接报错退出**，并打印可复制的迁移命令；
- `--probe` 与 `--commit` 互斥；
- `--commit` 不带 `--yes` 时要求手动输入确认词（`GO` 或配置里的 `keyword` 原文），确认词闸门严格位于写配置之前；
- `--commit` 路径无论是否带 `--yes`，启动前都打印下单摘要（演出/票档/观演人/场次）并倒数 3 秒，`Ctrl-C` 可随时取消；
- 运行模式判定与执行**同源**：`mobile/config.py` 新增 `read_runtime_mode`（四态），废弃 shell `grep` 解析 JSONC，屏显 / 改写判定 / 实际执行三者读同一真相源。

涉及文件：`mobile/scripts/start_ticket_grabbing.sh`、`mobile/config.py`、`mobile/prompt_runner.py`

### 2) 用户视角圆桌评审 → 8 项 backlog（PR #54）

以 5 个用户画像（抢票小白 / 技术资深 / 高频抢票党 / 多设备运维 / 风控安全）圆桌评审，产出 16 条 backlog，本版落地 8 条 implement-now：

- **U-01** `--commit` 强确认闸门（见上）
- **U-02** 入口脚本未知参数 fail-fast：`--porbe` 等 typo 一律报错退出，不再被静默吞掉直达真下单；`prompt_runner` 关闭 argparse 前缀缩写
- **U-03** 运行模式判定与执行同源（见上）
- **U-04** README / quick-start 配置示例与 `config.example.jsonc` 单源对齐（`CONFIG_EXAMPLE` 标记块两文档逐字节相同），清除 `udid`/`item_url` 等幽灵字段；30+ 守卫测试防漂移
- **U-05** 启动期配置防护：占位符黑名单（模板未填即中文报错）、废弃字段迁移警告、未知字段拼写提示、`serial` 精确预检、`ANDROID_HOME` 软化（有 `adb` 即放行，不再强制 Android Studio）；新增 `mobile/scripts/lib/preflight.sh`
- **U-06** 配置写回安全：注释保留 + 文件锁（`fcntl`/`msvcrt`/no-op 三级降级）+ `.bak` 备份 + 原子替换——模式切换不再剥掉配置里的护栏注释
- **U-10** 快速重试提交路径强制复用 `verify_order_result` 同源验证，禁止仅凭点击虚报成功；未知结果 fail-closed（`submit_unverified`）防重复下单
- **U-12** 可编排性：语义化退出码 + `run_summary.json` 机器可读摘要 + `--serial`/`--result-json` 旗标

评审报告与设计存档：`docs/bugs/2026-07-11-usability-roundtable-report.md`。

### 3) 抢票正确性与信任修复

- **PR #53**：#41 开售轮询（大麦 ≥9.0.2x 详情页 CTA 改为 Canvas 自绘，`btn_buy_view` 移除后开抢延迟从 ~8s 收紧到亚秒）、#45 票价文本误解析、#50 演出信息识别、#51 详情页标题不一致导航返回。
- **PR #55**：probe 模式遇到账号**预先存在**的未支付订单弹窗时，不再误报「抢票成功」；据实分流为新 outcome `preexisting_pending_order`（探测提醒，非本次提交）。正式/开发模式语义不变。

### 4) 多场次 / 价格 / NLP / 页面探测健壮性

- **#25 多场次**：新增 `select_session` 与 `SessionNotFoundError`，`PageState.SESSION_PICKER` 状态识别；`rush_mode` 拆分为 3 个子开关（`rush_skip_session`/`rush_skip_price_dump`/`rush_aggressive_retry`，保留 alias 兼容）——多场次场景强制选场，杜绝直冲 `price_index` 失败。
- **#31 价格**：config 加载期校验 `price_index` 范围；`detect_price_panel_state` 区分 loading/ready/sold_out/unknown；失败自动 dump `tmp/price_dump_*.xml`；新增 `PriceSelectorError`/`SoldOutError`。
- **#26 NLP**：apply 模式无法解析时交互式 fallback（含 `--non-interactive`）。
- **#24/#23/#28 页面探测**：`page_probe` unknown 阈值告警 + 自动 dump + `force_state`；搜索结果可见性等待 + 0/1/N 结果分流；首页探测加超时 + UI dump + `HomeNotReadyError`。

### 5) damai_app 包化重构 + 可观测性

- **PR #44**：`mobile/damai_app.py` 拆分为包（`orchestrator` / `sale_waiter` / `state_probe` / `recovery_strategies` 等），零行为变更，公共接口保持向后兼容。
- **PR #46**：结构化日志事件（`log_event`）+ 启动期环境快照（`env_snapshot`）+ 失败工件自动留档；`mobile/proc_utils.py` 统一 subprocess 编码（`utf-8`/`errors=replace`，修复 Windows GBK 解码）。

### 6) 真机验证捕获并修复的 4 个 bug

- **BSD sed 可移植性**：`preflight.sh` 提取 `serial` 的 `sed ...;t;...` 分支写法在 macOS BSD sed 报 undefined label、静默输出空 → serial 精确预检在 macOS 从未真正执行（Linux CI 因 GNU sed 反而通过，形成「macOS 假绿掩盖 Linux 真红」）。改为 `sed -E -n 's/.../p'`。
- **bash 3.2 吞全角字符**：`$VAR` 紧跟全角括号时，macOS bash 3.2 把全角首字节并入变量名，变量值与半个字符一起消失。3 处改 `${VAR}`。
- **详情页标题读空死循环**：某机型上标题控件持续不可读 → similarity=0 误判 mismatch → 正确演出反被拉入黑名单。改为三层兜底：延长轮询 → 场馆包含匹配（`venue_fallback`）→ 锚定 WARNING 放行。
- **probe 虚报成功**（见 §3 PR #55）。

### 7) ops / 测试基础设施

- 手动真机回归 runbook 标准化（PR #47）；self-hosted runner 真机 E2E workflow 框架（PR #48，dry-run 默认禁用）；「当前不支持的功能」文档段落（PR #49）。
- README 四象限评审补齐入门门槛 / 目录 TOC / 观演人添加 how-to / 风险合规披露（PR #56）。

## 兼容性与行为变化（升级必读）

### 1) 真实下单旗标变更（BREAKING）

- 旧：`start_ticket_grabbing.sh --yes` = 真实下单。
- 新：`start_ticket_grabbing.sh --commit --yes` 才真实下单；裸 `--yes` 直接报错退出并给迁移指引。
- 依赖旧行为的外部 cron / expect 脚本必须迁移到 `--commit --yes`。这是刻意的资金误操作防护。

### 2) 退出码语义化（BREAKING）

- `python -m damai_app` 及脚本失败时不再恒 `exit 0`，改为返回语义化退出码（`0` 成功 / `10` 重试耗尽 / `11` 不可重试失败 / `12` 配置或设备错误 / `130` 中断；`13` 预留）。
- 依赖「总是 exit 0」的旧编排需按 README「退出码与运行摘要」小节迁移。

### 3) 配置占位符启动期硬校验

- `config.jsonc` 里 `serial`/`users` 仍是模板占位符（如「你的设备序列号」）时，启动即中文报错，不再一路跑到订单页才失败。
- 直接 `cp` 模板后必须先填真实值。

### 4) `rush_mode` 拆分为 3 个子开关

- `rush_mode` 保留为 alias；多场次场景即便配 `rush_skip_session: true` 也会被强制选场并 warning。

## 从 v0.4.1 升级到 v0.5.0（建议步骤）

1. 拉代码并安装依赖
   ```bash
   git pull
   poetry install
   ```
2. 检查配置：本版未新增必填字段，但请确认 `serial`/`users` 已填真实值（占位符现在会启动即报错）。
3. 先做安全探测（推荐）
   ```bash
   ./mobile/scripts/start_ticket_grabbing.sh --probe
   ```
4. 正式抢票（注意新旗标）
   ```bash
   ./mobile/scripts/start_ticket_grabbing.sh --commit --yes
   ```

## 性能基准（v0.4.1 baseline → v0.5.0 实测）

`bash mobile/scripts/benchmark_hot_path.sh --runs 3`（device c6c4eb67，起始 detail_page，强制 `if_commit_order=false` 安全模式，停在「立即提交」前）：

## 已知边界

- 线上风控、库存波动与验证码仍会影响最终结果，自动化只提升效率，不保证 100% 成功。
- 多场次（音乐节）场次自主选择仍有边界场景。
- 验证码人工接管、排队墙状态机、开抢时钟校准等 7 项 plan-only backlog 已有设计方案，待后续真机验证窗口落地（见评审报告）。
- `release.yml` 仅从 tag 注释创建 GitHub Release，不产出 binary asset；mobile 是源代码方案，用户通过 `git pull` + `poetry install` 升级。
